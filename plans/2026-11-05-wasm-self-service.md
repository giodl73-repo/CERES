# Reproducible CERES reader delivery

## 1. Goal and strongest objection

Make the existing production reader independently inspectable and reproducible,
using its original Rust lenses and exact draft inputs. Successful execution can
repeat unvalidated assumptions perfectly. Therefore delivery proof must not be
presented as a funding decision, economic validation, equipment safety evidence,
governance design, historical certification or catalog lifecycle promotion.
This is an additive software delivery plan, not a new catalog/research/playbook
plan or an amendment to economic formulas in the design spec sections6–8.

## 2. Original task and native boundary

Baseline5a69e2dd729858531e27017c6f3b8da89f9e58a2 is public main. The current
reader selects one of two bundled draft forge entries, settlement scale and
bounded participation/wage controls, returning all3 original market/coop/civic
LensResult values, population/households and draft status. Preserve formulas,
constants, parser, thresholds, notes, defaults, complete original result export,
share/reset and catalog links. Preserve unfavorable verdicts without ranking
them into an investment recommendation. Existing own inputs remain practical
within this chosen sensitivity task; do not invent new catalog fields or data.

Native CLI catalog runs, entry comparisons, events and SCENARIUM packets remain
available in complete native source/download instructions. Filesystem ingestion,
custom catalog runs, comparison/evidence-packet tasks are not claimed as existing
browser features or silently replaced by a demo. Keep all original native Rust
and CLI behavior, and preserve original output/file controls before modifications.
No new scoring, synthetic catalog, research promotion or model-data update.

## 3. Evidence before delivery changes

Freeze original native tests/format/strict Clippy, lock identities, CLI complete
stdout/stderr/exits and representative original event/packet files outside the
mutable Cargo target. Add only a native test control over ceres_web::evaluate;
execute actual unknown-target evaluate_json with identical typed inputs, both
entries/all scales, low/high/boundary and intermediate participation/wage cases,
invalid/nonfinite/width cases. Record JS integer ABI conversion separately from
the original native usize guard and use strict browser admission for its range.
Do not claim compiled code alone proves native/WASM parity or economics.

## 4. Complete source, dependencies and grants

Create source from exact Git blobs/modes with a manifest, preserving the whole
native repo, catalogs, research, roles, workflows, scripts and existing LICENSE.
Resolve the original locked registry and Git sources, including transitive
RUNE and direct RALLY/RLINE/SCENARIUM, without changing pins. Bind full original
dependency file inventories/checksums, actual upstream notices/root grants and
toolchain requirements; do not replace complete sources with a Cargo.lock or
URLs. Preserve prior grants and CERES software MIT/content CC BY-NC4 scope;
third-party material keeps its own terms. Do not invent an upstream license.

Rebuild from a new independent input tree/Cargo home and from the verified source
ZIP outside any Git repository, without owner cache, TRACKER paths, credentials
or package acquisition. Keep the shared compiled target and say it was reused;
do not call this a fresh compiled cache or bundled toolchain. Rust1.95.0/linker,
unknown target, wasm-bindgen0.2.127, Python/Node/browser remain documented installed
prerequisites. Verify archive paths/modes/blob identity and reject corrupted
source, input, module, manifest or unsafe export/restore destinations. Preserve
vendor dotfiles, checksums, original manifests, license files and source context.

## 5. Browser/download behavior

Keep the useful immediate example and original controls/three lenses. Add exact
Rust source/archive, distinct compiled module, actual dependency notices and
build identity/instructions, independent of engine availability. Keep original
result values/notes/inputs separate from formatted display and original catalog
bytes. Exports and source links bind the submitted snapshot/source commit,
not a newer control state or a mutable branch advertised as exact provenance.

Use a dedicated worker with explicit boot/compute deadlines, actual termination
on cancel/restart, retry and generation/request fencing. Clear/disable obsolete
exports on edits/errors/reset; no stale result labeled with new inputs. Test
loading/empty/invalid/failure, unavailable WASM, recovery, keyboard and mobile
layout, rapid edits/reset, exact own-input export/share and source/download access.
No uploads, persistence, separately operated API or account required for public
execution. Preserve project-site paths and original draft/research boundaries.

## 6. Build, artifact and hosted gates

Use clean committed source/locks and source-bound native/WASM/browser proof.
Keep within the existing5MB site budget or explicitly review a justified source
download layout without removing required code or licenses. Record actual bytes
and scoped startup/evaluation observations with environment/input size.
Validate before deploy; bind downloadable artifact/source/runtime/UI/build
manifest and verify receiver corruption controls. Hosted Windows/Linux source
replays and downloaded-artifact identity/access remain distinct from local proof.
Preserve least-privilege Pages deployment and existing access boundary. Default
main merge/deploy follows complete reviewed evidence; TRACKER pointers change
only in an explicit snapshot pulse after child work is validated and pushed.

## 7. Review and sequencing

Apply skills/ceres-panel/SKILL.md to this complete plan using all6 full role files
and their lens.verify/rubric contributions. Record AI-simulated composite reviews
by the implementing agent; no independent human panel, funder approval, numeric
rubric grade or validated catalog status is implied. Editorial/board promotion
of catalog/economic/historical claims is outside this software plan. Keep the
scope lens explicit; flag genuine spec changes instead of silently expanding.

Stages: original/parity evidence; complete authorized inputs and source custody;
independent checkout/archive rebuild; worker/download improvements and full
browser/receiver; hosted artifacts; final review/child default delivery; separate
TRACKER checkpoint/snapshot. Each stage stays open until actual evidence proves
it. No partial milestone closes the whole plan or the portfolio goal.

## 8. Validation and rollback

Run cargo test --workspace --all-targets --locked, cargo fmt --all --check and
strict workspace/all-feature Clippy with the original lock; release unknown
target build; original CLI/native file controls; typed native/WASM parity;
source/dependency/receiver negative controls; original committed browser tests
plus meaningful task/lifecycle/download/keyboard/mobile cases. Record failures
and corrected reruns separately. Reverting delivery/test/tool changes must leave
original core math, catalogs, simulation outputs and legacy grants unchanged.
Protected canonical checkout, TRACKER23 entries, shared target, historical
research/data and other owner sessions remain untouched.

## 9. Source download layout and explicit budget review

The exact-source bootstrap at9499757890b1c0da98b632c8da7dbf685e802a95
measured6,853,502 bytes for the full source ZIP, including the4,830,483-byte
input capsule (validation/exact-bootstrap/qualification.json). It cannot fit
with the runtime under the original5MB total. Keep all source, content, original
manifests, prior grants and validation records. Serve the complete pinned ZIP
under `downloads/`, fetched only on request. Keep the runtime and its independent
notices/build/source links below5,000,000 bytes; cap all optional download files
together at12,000,000 bytes and the entire site at17,000,000 bytes. These are
delivery limits justified by the measured complete package plus bounded growth,
not economics or a promise about download time. Report each category separately.
No source-kit fetch on page load, no CDN/account/API, no removed license/code.

Bind the whole Git tree and exact commit object, every original file blob/mode,
locked input capsule and notices in a standalone source manifest. The receiver
must verify a trusted external build-manifest SHA, every deployed file and the
runtime/source identities before any restoration. Reject unsafe/duplicate paths,
corrupt files/manifest/module/source, Git tree omissions or altered modes, existing
or linked destinations and compiled-target overlap. Test valid outside-Git source
restoration/bootstrap and deliberate failures. A manifest proves integrity against
its supplied trusted identity, not author authentication or equipment feasibility.
Rebuild using installed prerequisites and explicitly reused compiled target.

Review this amendment with all six simulated composite voices before changing
the builder budget. No catalog/schema/economic/research spec change or promotion.
